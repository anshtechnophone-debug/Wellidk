The three `github.com/topics/telegram-bot`, `telegram-music-bot`, and `telegram-bots` URLs are mutable topic/discovery pages, not individual repositories. They have no single source tree, dependency set, or license to audit. No topic-page code was selected or reused.

## Architecture Decision

Use one primary framework, `python-telegram-bot` 22.6, with async SQLAlchemy 2.0, SQLite for single-process local/small installs, and asyncpg/PostgreSQL for larger installs. Keep authorization in a shared permission function and durable moderation state in the database. No candidate code is imported. A future group-call music service should remain an optional separate worker because Yukki's Pyrogram/Py-Tgcalls assistant-account requirements conflict with a minimal Bot API process and require independent operational and licensing review.

## Dependency And License Notes

The installed application dependencies and their license pointers are listed in `THIRD_PARTY_NOTICES.md`; resolve and scan the complete transitive dependency graph during release builds. No credentials, vendor APIs, or optional source integrations are required by the current implementation.
